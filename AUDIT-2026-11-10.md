# Независимый аудит PZ/PZA на Windows, 2026-11-10

Исправлена ошибка обратимости публичного преобразования PZA; сохранена
небольшая оптимизация времени упаковки без изменения encoded bytes.
Общего улучшения степени сжатия **нет**. Отклонён отдельный palette-эксперимент.
Linux host/solid и UEFI остаются вне проверенной платформы этого этапа.

База: `455106542aa610635c2e01c05a11d214c94a611d`, ветка `PZ/PZA-models`.
Проверенный код: `c9dacde3933877c3b0f921ba83b2c830e83520e8`.
Рабочая ветка: `audit/windows-pages-20261110`. Отчёт и сырые данные идут
следующим коммитом. Remote проверен:
`https://github.com/awesomejiy67-source/pz01-pz02-alpha-mini.git`.
GitHub сообщил default branch `Main`; локальная база выбрана из явной
`PZ/PZA-models`. Исходный workspace был пуст, незакоммиченных пользовательских
изменений не было. В клоне создана отдельная ветка. AGENTS.md в проекте и
проверенных родительских каталогах не найден. Push/merge не выполнялись.

## Что изменено и почему

| Статус | Место | Воспроизведение / измеримый эффект |

Нет нового wire, API/ABI или внешнего движка в page-библиотеке. Старые
PZ01/PZ02/PZ03/PZA1 значения не переопределены. Проверка checksum не отключена.
Исправленный inverse публичного source-фильтра читает ранее успешно
производившийся standalone результат; это не расширение допустимого page payload.

## Проверенная архитектура и реальные бюджеты

**A: PZ pages.** PZ01 ищет до 512 предыдущих байт, match до 34. PZ02 использует
историю текущей страницы (offset до 2047), hash table 1024, цепочку до 16
кандидатов, long LZ/RLE и palette≤16. Scratch head+chain — 6144 байта.
RAW-fallback уже был: максимум raw+16, включая пустой вход. Заголовок 16 байт,
FNV32. PZ03 сохраняет PZ02 и сравнивает полный размер envelope+inner; fast
вообще не ищет predictors, balanced оценивает до девяти и кодирует один,
max кодирует до девяти. Меньший результат не означает меньшее encode-время.

**B: PZA.** Замороженные 64 токена, 192 байта lookup accelerator плюс строки
и указатели в коде; словарь заметно привязан к Atom. Слова сопоставляются
целиком, FF экранируется. E8/E9 — обратимый byte scan с modulo-32 поправкой,
не дизассемблер. Цветовой фильтр — G/R−G/B−G, planar delta, отдельная alpha;
он не использует двумерные соседние строки изображения. Исходный PZ02,
прямой transformed payload и nested PZ02 сравниваются с полной ценой metadata.
Поэтому фильтр не ухудшает размер относительно PZ02, но может стоить CPU.
PNG/JPEG в таблице подаются явному page kind=1; host auto-passthrough — иной путь.

**C: Host/solid.** Не менялся. Linux native использует zlib/OpenSSL, heap внутри
библиотек, blocks 65536, history≤512KiB, cap raw256MiB/archive512MiB, до 512
файлов. Это отдельный формат PZ03SL01 с manifest, CRC32/SHA256 и fsync. Нельзя
переносить его показатели на no-heap страницы. PZAF0001 Python asset container
тоже отдельный host-путь. Нового host vs Zstd/7-Zip benchmark здесь нет;
исторические результаты не выдаются за повторённые.

Embedded-контракт сохранён: C11, raw≤2048, независимые страницы, disjoint
caller buffers, отсутствие heap и скрытого межстраничного словаря. Численного
общего лимита stack/RAM для этой standalone библиотеки в исходниках не задано.
Упоминание Atom≤1MiB относится к внешней EFI-интеграции и здесь не проверено.

## Условия и критерии

Windows NT 10.0.17763 x64; CPU, сообщённый системой: Intel Core i3-3220 @3.30GHz,
2 cores/4 logical. LLVM/MinGW 20261104, clang 23.1.5,
`-O2 -std=c11 -Wall -Wextra -Werror -Wno-misleading-indentation`.
Baseline и итог собраны одним компилятором; общий native измеритель одинаков.
LZ4 1.10.0 default block, Zstd 1.5.7 level1, zlib 1.3.1 level1 также `-O2`.
Точные версии/URL/SHA, команды и stdout/stderr находятся в evidence.
Source hashes различают реально компилировавшиеся Windows checkout bytes и
Git blobs (CRLF/LF); обе формы записаны в verified-code.json. Evidence защищено
от Git newline conversion через отдельное правило .gitattributes.
Makefile и Ubuntu CI прочитаны; команды C воспроизведены непосредственно
компилятором с Makefile flags. Сам GNU Make/Ubuntu CI здесь не запускался.

22 фиксированных набора, независимые страницы на одинаковых границах 2048.
Исходники проекта и BSD/zlib C/C++/текст, собственный PE, PNG/JPEG/ZIP, смешанный
набор, равномерный шум, BGRA с 0/5/25/75% внесённого шума, JPEG-derived BGRA.
Seed, источники, train/validation split и SHA256 каждого входа — в
[`corpus.json`](evidence/audit-20261110/corpus.json). Точные байты с лицензиями
сохранены в inputs.zip/corpus-licenses. PE — baseline quickstart, а не независимый
набор приложений; изображение — один открытый fixture. Размеры входов ≤64KiB.
Широкий стандартный/production корпус и несколько машин не проверены.

Пороги записаны до production-оптимизации в
[`ACCEPTANCE.md`](evidence/audit-20261110/ACCEPTANCE.md): byte-identical wire,
ни одной size-регрессии, validation encode geomean≤1.05, отдельные encode/decode
регрессии≤20%, целевой выигрыш≥10%, рост `.text`≤512Б и frame≤256Б.
Это локальные критерии принятия, не выдуманные аппаратные ограничения.

Итог: пять батчей после прогрева, baseline/final чередуются; target batch100ms,
число циклов ограничено 5000 для самых быстрых операций. Время снимается внутри
C, без генерации входов, запуска процесса и файлового I/O. Каждый codec/input
проверен byte-for-byte. CPU не изолирован; разброс публикуется. Промежуточная
palette-concurrent серия с параллельной sanitizer-сборкой сохранена и не
используется как чистое измерение. Последняя серия выполнялась отдельно.

PZ несёт FNV32, zlib Adler32; raw LZ4 не имеет header/checksum, Zstd frame — без
checksum. Это сравнение независимых кодеков, не равноценных файловых контейнеров.
Только быстрые режимы конкурентов; sweep Zstd/zlib levels и trained dictionaries
не выполнялся. В таблицах есть все PZ03 усилия; победы над полным спектром режимов
конкурентов не заявляются. Host CLI/startup/I/O/fsync throughput не измерялся.

## Результат

Оптимизация прошла сохранённые критерии; машинный результат —
[`decision.json`](evidence/audit-20261110/decision.json). Все 198 сочетаний
codec/input имеют прежние encoded bytes. PZA validation encode geomean
отношения after/before = **0,97216**. Это среднее отношений времени, не прирост
общей пропускной способности. На PE encode −17,36%, на README −8,02%, на ZIP
−11,89%. Узкие synthetic выигрыши: small_alphabet −46,74%, long_prefixes −45,57%.
Их нельзя распространять на обычные исходники или изображения.

Максимальная PZA encode-регрессия: PNG +3,34%; decode: bgra_noise_0 +9,09%.
Все положительные изменения времени, включая неизменённые контрольные кодеки,
перечислены в [`all-time-regressions.csv`](evidence/audit-20261110/all-time-regressions.csv).
Отдельные небольшие изменения у неизменённого кода показывают шум измерений.
Результаты промежуточного identity-прогона (включая JPEG +26,7%) не скрыты;
решение принято по заранее предусмотренной полной итоговой серии, не по
лучшему отдельному повтору и без изменения порогов.

## Память и код

Сумма `.text` шести page-объектов: **12574 → 12622Б (+48)**. Импортируемый
CRT/memcpy/memcmp и внешние benchmark DLL в эту сумму не входят. DLL file size,
все sections, undefined symbols и source/binary hashes сохранены. В page-объектах
нет malloc/calloc/realloc или ссылок на zlib/LZ4/Zstd/OpenSSL.

Compiler frames неизменны: page_pack6648Б, pz03_page_pack4296Б,
pza_pack4232Б, pza_unpack2152Б, pz03_page_unpack2168Б; остальные — в
[`final-resources.json`](evidence/audit-20261110/final-resources.json).
Вложенные вызовы суммируют стек, caller buffers живут отдельно. Frame нельзя
называть всей RAM. Нулевая heap-аллокация не означает нулевую память.

Для каждого из 198 сочетаний сделано пять новых native процессов после
отброшенного прогрева, порядок чередовался. GetProcessMemoryInfo измеряет
PeakWorkingSet и PrivateUsage после encode/decode. Диапазон медиан PeakWorkingSet
2134016…2646016Б у обеих версий. Это включает CRT, DLL, OS и фиксированные
**525312Б буферов измерителя**; это не минимальная RAM кодека и не доказательство
равенства памяти всех алгоритмов. CSV содержит отдельные значения и разброс по
каждому входу; Zstd context sizes также сохранены в raw benchmark JSON.

## Проверки и оставшиеся сбои

- До и после: 5049 PZ01/PZ02 round-trips +5049 legacy reads +20196 mutations;
  PZ03:24000 profile round-trips,8000 size comparisons,120000 mutations,
  616 legacy cases; PZA:20000 round-trips,60000 mutations. Все прошли обычно
  и под ASan/UBSan. Нет утверждения о CI или UEFI.
- Новый public-transform regression: все2048 raw-длин, worst-case escape,
  короткий выход, UINT_MAX и недопустимые границы. Baseline воспроизводимо
  падает при1025/2050, финал проходит обычно и под sanitizer.
- Фиксированные hand-built PZ01/PZ02 fixtures: legacy overlap, нулевое/
  чрезмерное смещение, границы long LZ/RLE, max page, палитра, truncation и
  capacity. Старый и финальный код проходят обычно и под sanitizer.
- Cross-version differential seed0xA0112026:4097 raw cases,40970 совпавших
  encodings и81940 точных cross-decodes. Это конечная выборка, не доказательство
  одинаковости на всех возможных входах.
- `-fsanitize=fuzzer` недоступен для этого MinGW target; отказ сохранён.
  Выполнен ASan/UBSan property/mutation fallback: seed18111986,30000 случаев,
  7,242с при timebox60с. Точные malloc-границы input/output — только в harness;
  сами кодеки heap не используют. Для мутаций проверяются безопасность и
  contract bounds, а не обязательный отказ. Падений нет, минимизировать нечего.
- Пять portable Python asset/data-групп прошли на baseline и final: независимые
  transforms/token fixture, byte/pixel containers, rehashed corruption и
  max≤fast. Полная suite8 групп на обеих версиях:2 errors (CLI/POSIX и mkfifo).
  Прохождение negative frame-теста не доказывает работу Windows image adapter:
  CLI может отказать раньше на POSIX открытии.
- UDICT:24 теста,30 errors с учётом subtests; Python solid:15 тестов,15 errors;
  native syntax build:нет sys/syscall.h. Host I/O fault injection, traversal/
  symlink guarantees, native cross-language compatibility и host sanitizer
  здесь **не проверены**. Защиты не обходились. Это платформенные прежние сбои,
  не новые регрессии page-кода.
- Исправленные штатные benchmarks:72 page и42 PZA comparisons прошли; optional
  Atom datasets отсутствуют. Их числа лежат отдельно от основной22-case серии.

Сведения о failures/skipped сохранены в JSONL, а не заменены общим «всё зелёное».
Новых обнаруженных сбоев памяти/восстановления после исправления нет в выполненной
выборке; отсутствие всех возможных дефектов не доказано. FNV/SHA не являются
криптографической аутентификацией источника.
Внешний Atom `ATOM_FREESTANDING` adapter не проверен: `pz_memory.h` не входит
в этот репозиторий. Новая оптимизация использует обычный `memcmp`; предоставление
этого примитива в freestanding-интеграции нужно проверить до переноса в EFI.

## Checkpoint и следующий приоритет

Команды воспроизведения, версии инструментов, отдельный output directory и
команда отправки локальной ветки —
[`REPRODUCE.md`](evidence/audit-20261110/REPRODUCE.md).
Все raw measurements, corpus hashes, отклонённые опыты и лицензии доступны в
`evidence/audit-20261110`; старые AUDIT/PZA/ROUTER/JURY отчёты сохранены.

Следующий обязательный этап — отдельный Linux host baseline с пятью повторами,
полным no-clobber/traversal/symlink/I/O fault набором и честным Zstd/7-Zip
сравнением. Его отсутствие не позволяет назвать весь запрошенный cross-platform
аудит завершённым. Для page-кодеков следующий performance-вопрос — уменьшение
цены PZ03-max на шуме/смешанных данных без потери его проверенных кандидатов.
Возможность такого выигрыша пока гипотеза. Новые словари, 2D predictors,
изменение token ABI, универсальное превосходство над конкурентами не заявляются.
