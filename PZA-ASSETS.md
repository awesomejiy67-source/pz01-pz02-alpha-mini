# PZA1: код и снимки Atom

Нативный C11, без heap, до2048 исходных байтов на страницу. Совместно
разрабатывается с Atom; это дополнение к PZ02/PZ03, а не новый универсальный
формат для всех прежних архивов PZ03. GPL-3.0-only, N.A.N.O. Boot Tech.

| kind | Назначение | Обратимое преобразование |
|---:|---|---|
|0|Обычные байты|PZ02|
|1|Исходники C и текст программ|64 фиксированных ASCII-идентификатора; маркер255|
|2|Хранение x86/x64-байтов|Нормализация32битных E8/E9 displacement по позиции в странице|
|3|BGR8|G, R−G, B−G; разность соседних пикселей; отдельные плоскости|
|4|BGRA8|То же, плюс отдельная плоскость разностей alpha|

Это комбинации известных методов. X86-фильтр сканирует байты и пропускает4
байта displacement после E8/E9; не является дизассемблером. Даже ошибочное
предположение о типе данных обратимо. Маркер255 в исходнике экранируется как
255,0; номера1..64 — замены. Слова и их порядок заморожены версиейPZA1.
ASCII-идентификатор заменяется целиком, без изменения регистра, Unicode,
пробелов, строк или комментариев. Хеш-таблица192Б ускоряет поиск и не меняет wire.

Encoder сохраняет PZ02-кандидат и пробует одно профильное преобразование.
Преобразование хранится напрямую либо через PZ02, по фактическому размеру.
PZA1 побеждает только при строгом уменьшении с учётом всех16байт envelope.
Размер всегда ≤PZ02. Это минимум среди проверенных кандидатов, а не теоретический
предел сжатия. Время может вырасти; неподходящие типы возвращаются к PZ02.

## Страница PZA1

| Смещение | Размер | Поле |
|---:|---:|---|
|0|4|ASCII PZA1|
|4|4|LE исходная длина1..2048|
|8|4|FNV1a32 исходных байтов|
|12|1|kind1..4|
|13|1|0=непосредственное преобразование;1=вложенный PZ02|
|14|2|LE длина payload|
|16|переменный|Payload|

Вложенность только одна: method1 допускает исключительно PZ02. Никаких ссылок
на внешние словари, исполняемых рецептов и рекурсивных контейнеров. PZA decoder
также читает старые PZ01/PZ02/PZ03 pages; старые decoders не читают PZA1.
Header-only info откладывает checksum/decode до обращения к странице. При
ошибке actual=0, частично изменённый output необходимо отбросить. I/O disjoint.
FNV — обнаружение случайной порчи, не аутентификация.

## Файлы на host

```sh
make build/libnano_pz.so
python3 tools/pza_assets.py pack agent.c agent.pza
python3 tools/pza_assets.py pack BOOTX64.EFI boot.pza --effort max
python3 tools/pza_assets.py unpack agent.pza agent-restored.c
python3 tools/pza_assets.py frame picture.png pixels.pza
python3 tools/pza_assets.py unpack pixels.pza pixels.bgra
python3 tools/pza_assets.py unpack pixels.pza restored.png --png
python3 tools/pza_assets.py info pixels.pza
```

`pack` сохраняет исходный файл побайтно, включая PNG/JPEG и метаданные. Auto
распознаёт их сигнатуры и в fast пропускает бесполезный поиск. Уже сжатый файл
может стать немного больше из-за контейнера. `--effort max` дополнительно
пробует PZ03 max на каждой странице и выбирает меньший результат; упаковка
медленнее, распаковка не повторяет поиск. Default fast не означает быстрее
любого другого кодека — он ограничивает число проб.

`frame` — другая, явно выбранная операция: хранит декодированные BGRA8-пиксели,
размер и alpha. Не сохраняет исходное PNG/JPEG-кодирование, EXIF/ICC/другие
метаданные. Поддерживает один RGB/RGBA8 кадр;16битные, palette/CMYK и анимация
отклоняются, чтобы не скрывать квантизацию/потерю кадров. Масштабирование и
EXIF auto-rotation не выполняются. `--png` восстанавливает те же RGBA8-пиксели,
но не исходный файл. Нужен Pillow только на host, не в UEFI.

Host-контейнер PZAF0001: `<8sBBHIII32s>` header: magic,kind,flags,reserved0,
raw_size,width,height,raw_SHA256. flags0 или1(frame). Далее канонические блоки
`<u16 raw_count,u16 encoded_count>` и payload; encoded_count0 означает raw.
Шаг2048 или2046 дляBGR. В конце SHA256 всех предшествующих байтов, включая
метаданные. Encoded_count строго меньше raw_count. До16МиБ raw,4096 на сторону,
для frame width×height×4=raw_size. Exact input consumption, checksums и границы
проверяются до публикации. SHA не подтверждает автора. Выход no-clobber через
temp+link; fsync файла есть, crash-durability родительской директории не обещана.
FIFO, symlink и изменение входа отклоняются. Файловые metadata не сохраняются.

## Atom

В Atom v0.13 этот же PZA codec встроен в EFI. Runtime PZ02-pager остаётся прежним;
lazy reader дополнительно понимает PZA1. Отдельный asset store держит один blob
до61440raw байт в65536Б фиксированном пуле. Код и кадр делят этот слот.
При запуске valid store старый слот инвалидируется; отмена в процессе оставляет
NONE. Invalid arguments и отмена до старта сохраняют старый blob. Неполные
данные никогда не выдаются как valid. После перезапуска всё теряется.

UEFI: `snapshot` читает текущую область GOP160×96 BGRA, сжимает и проверяет decode;
`asset-code ТЕКСТ` сохраняет фрагмент кода, `asset-check`, `asset-info`,
`asset-clear`. Камера, загрузка PZAF с диска и исполнение распакованного кода не
добавлены. Исполняемые секции самого EFI продолжают работать обычным способом.
Сжатые payload могут быть малы, но фиксированный пул всё равно занимает65536Б
RAM. Пиковая память, scratch и стек включены в собственный бюджет Atom≤1МБ.
