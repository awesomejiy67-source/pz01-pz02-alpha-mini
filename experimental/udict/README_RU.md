# PZ03 ALFA / UDICT Research v0.2

**Экспериментальный модуль** N.A.N.O. Boot Tech — `PZ03UD02` (не ZIP и не `PZ03STR4`).

Алгоритм реализует идею пользователя: короткий код для повторяющейся последовательности (`return`, `exit` и др.) с **общим словарём для всех файлов одного архива**. Словарь встроен в сам архив, поэтому распаковка не зависит от внешнего файла. Отдельные словарные коды **не обязаны совпадать между двумя разными архивами**. Формат может измениться, пока это лаборатория.

## Пример

Из каталога с исходниками PZ03 ALFA:

```bash
python3 experimental/udict/udict.py pack demo.pzud main.py script.lua --mode balanced
python3 experimental/udict/udict.py verify demo.pzud
python3 experimental/udict/udict.py unpack demo.pzud new_folder
python3 -m unittest discover -s experimental/udict/tests -v
python3 experimental/udict/tests/hell_jury.py
```

Если используешь отдельную папку `PZ03-UDICT-LAB-v0.2`, вместо пути `experimental/udict/udict.py` используй `udict.py`.

**Важное:** папка `new_folder` должна отсутствовать; никогда не перезаписывается существующий результат. Вход: до 512 обычных файлов с уникальными безопасными именами (только один уровень). Пределы: 256 МиБ суммарного распакованного вывода, 512 МиБ архив, блоки 128 КиБ, словарь до 64 фраз по 4–48 байт, до 64 предыдущих блоков в истории и 32 КиБ хвоста для DEFLATE. Работает на Linux; обязательны `O_NOFOLLOW` и `renameat2(RENAME_NOREPLACE)`.

## Архитектура

1. Из ограниченных образцов файлов строится *кандидатный* словарь.
2. Словарь отклоняется, если предварительный тест не показывает ожидаемой окупаемости. Для шумных данных обучение досрочно прекращается.
3. У каждого блока есть варианты: RAW; zlib; токены; zlib поверх токенов; FILL; точная ссылка на предыдущий блок; DEFLATE с 32-КиБ словарём из предыдущих исходных байтов.
4. Выбирается минимальная **фактическая длина payload** среди проверенных вариантов. Накладные расходы записей одинаковы; стоимость словаря оценивается отдельно на обучающих образцах. Это **не глобальный математический оптимум**.
5. Испорченные токены, недопустимые ссылки, oversized zlib и повреждённые метаданные отвергаются. CRC32 блока + SHA-256 исходных байтов + SHA-256 **всего сериализованного архива**.
6. `verify` проверяет без создания распакованных файлов. `unpack` распаковывает в скрытую временную папку и публикует только после успеха.

## Три режима

- `fast`: zlib level 1, жадная токенизация.
- `balanced`: zlib level 3, оптимальный по длине токеновый разбор блоков до 512 Б.
- `max`: zlib level 6, оптимальный разбор до 8192 Б.

В отличие от предположений первоначальной идеи, словарь не всегда помогает; код `1` не обязан означать `return`. Результат зависит от входа и обучения.

## Проверки и ограничения

Смотри `HELL_JURY_REPORT_RU.md`, `benchmark_results.json`, `compare_alfa_results.json`, `hell_jury_results.json`. В проверенном запуске: 24 группы unittest, 12 000 мутаций (отклонены все 12 000), сравнения с PZ03 ALFA, Zstd, gzip и xz. `make test` оригинальной ALFA запущен отдельно и прошёл. Это не доказательство отсутствия уязвимостей.

SHA-256 не защищает от намеренного злоумышленника, способного пересчитать хеш. Подписи и шифрование отсутствуют. Не сохраняются владельцы, права, времена, каталоги, симлинки. Проверка `fsync` без аппаратной имитации внезапного обесточивания не равна доказанной crash-consistency. Нельзя применять для единственной резервной копии.

### Практический результат

Динамический словарь — исследовательская реализация известных идей словарной компрессии. Современные Zstandard и Brotli также используют словари, поэтому мировая научная новизна не заявляется.

- Zstandard dictionary builder: https://github.com/facebook/zstd
- RFC 7932 (Brotli static dictionary): https://www.rfc-editor.org/rfc/rfc7932.html

Код предназначен для исследовательской ветки рядом с исходной PZ03 ALFA, **старые `PZ03STR4` архивы читает только исходный `pz03.py`**. Ни GitHub, ни исходный опубликованный архив не менялись.
